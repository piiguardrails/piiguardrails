Step-by-Step Deployment Instructions

STEP 1 • Deploy Template in Azure Portal

Choose whichever deployment method fits your workflow best:

Method 1: 1-Click Azure Portal Link

Click the Deploy to Azure Portal button above. Azure Portal loads the template directly from the verified URI.

Method 2: Template Editor (Offline / Fallback)

Click Copy ARM JSON. In Azure Portal search for Deploy a custom template > Build your own template in the editor > Paste > Save.

Once loaded, select your subscription, resource group, and review the template parameters:

adminStudioPassword Master password for the Studio Web UI (admin). Minimum 8 characters.
adminPasswordOrKey SSH public key or password for SSH / root access to the Ubuntu virtual machine.
allowedInboundCIDR Set to your corporate IP range (e.g. 203.0.113.25/32) or leave * for initial testing.
Preconfigured Compute Hardened Ubuntu 24.04 LTS on Standard_D2s_v7 (2 vCPU, 8GB RAM, 30GB SSD). Broadly available across all Azure availability zones.
STEP 2 • Access the Web Studio & API

Once the Azure deployment shows Deployment succeeded (typically ~2 to 3 minutes), navigate to the deployment Outputs:

Studio Web UI: http://<AZURE_PUBLIC_IP>:8000
Interactive OpenAPI Docs: http://<AZURE_PUBLIC_IP>:8000/docs

Log in with username admin and the password you defined in Step 1.

STEP 3 • Upgrade to Node-Locked Production

All audit logs, custom regex patterns, and compliance rules are saved in persistent encrypted storage at /opt/piiguardrails/data. You never need to rebuild or redeploy when your evaluation finishes:

  1. In the Studio Web UI, go to the Licensing tab.
  2. Copy your 16-character Server Hardware ID (e.g. A1B2-C3D4-E5F6-7890).
  3. Email piiguardrails@gmail.com with your Hardware ID and preferred tier (Standard or Enterprise).
  4. Paste your issued commercial key into the license field and click Activate.
