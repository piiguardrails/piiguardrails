Step-by-Step Deployment Instructions

STEP 1 • Launch CloudFormation Stack

Click the Launch on AWS EC2 button above. The AWS CloudFormation Quick-create wizard will open in your AWS console. Configure the following parameters:

AdminPassword Master password for the Studio Web UI (admin). Avoid generic passwords.
AllowedInboundCIDR Set to your corporate IP range (e.g. 203.0.113.25/32) or leave 0.0.0.0/0 for sandbox trials.
InstanceType Default is t3.medium (2 vCPU, 4GB RAM). Higher tiers (c6i.large) available for high-throughput loads.
TrialLicenseKey Pre-populated with a free evaluation key (10,000 requests quota). Leave unchanged to start evaluating immediately.
STEP 2 • Access the Web Studio & API

Once CloudFormation displays CREATE_COMPLETE (typically ~2 to 3 minutes), click the Outputs tab:

Studio Web UI: http://<EC2_PUBLIC_IP>:8000
Interactive OpenAPI Docs: http://<EC2_PUBLIC_IP>:8000/docs

Log in with username admin and the password you defined in Step 1.

STEP 3 • Upgrade to Node-Locked Production

All audit logs, custom regex patterns, and compliance rules are saved in persistent encrypted storage at /opt/piiguardrails/data. You never need to rebuild or redeploy when your trial finishes:

  1. In the Studio Web UI, go to the Licensing tab.
  2. Copy your 16-character Server Hardware ID (e.g. A1B2-C3D4-E5F6-7890).
  3. Email piiguardrails@gmail.com with your Hardware ID and preferred tier (Standard or Enterprise).
  4. Paste your issued commercial key into the license field and click Activate.

Security & Architecture Guarantees

🔒 100% In-VPC Data Sovereignty

No telemetry or inspection payloads ever leave your EC2 instance. All NLP tokenization and redactions run locally on your VM.

🛡️ AES-256 SQLCipher Database

Every database record is encrypted at rest using an automated 256-bit passphrase stored securely on the host.

💾 EBS Persistence Across Reboots

Your database and configuration persist across instance stops, reboots, and container restarts on the encrypted EBS volume.

⚙️ Auto-Restart Daemon

Managed via systemd supervisor to ensure high availability and automatic recovery in case of system reboots.
